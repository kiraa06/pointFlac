# Plan 4: Sound section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A professional Sound section with these blocks:
- ReplayGain and EBU R128 scanning;
- auto-headroom preamp;
- headphone correction;
- parametric and graphic EQ;
- tone controls;
- crossfeed;
- a true-peak limiter;
- crossfade;
- level-matched A/B;
- per-device profiles.

Pure stays the bit-identical default. The player shows plainly whether it is playing **Pure** and whether the output is **Hi-Res**.

**Architecture:**
- **Interactive blocks run in the render thread** after the ring (or the scrub voice), in Float64, from a compiled, immutable `SoundChain`. These are preamp, correction, EQ, tone, crossfeed and the limiter.
  - The chain is swapped in atomically and cross-faded over 10 ms. Dragging an EQ band is heard within one render buffer and never clicks.
  - Filters are designed for the output rate actually in use.
- **Per-track blocks run on the decode thread.** ReplayGain is a static gain per item; crossfade is an overlap mix of two decoders.
- **Pure** installs no chain, ignores ReplayGain and crossfade, and keeps today's bit-identical path.

**Tech Stack:**
- Swift 6 (strict concurrency), Swift Testing, XcodeGen, SwiftUI.
- Float64 DSP.
- Vendored libebur128 (MIT), as a C target the way libFLAC is.
- A port of bs2b (MIT).
- The OPRA dataset (CC BY-SA 4.0).

**Spec:** `docs/superpowers/specs/2026-10-20-pointflac-design.md`. Sections: §4.8 Sound, §5.2 pipeline, §5.7 signal readout, §6 testing, §11 library survey.

**Base:** `feat/sound` is cut from `feat/scrub-audio` (PR #3), because both change `RenderSource`. Merge `main` into it once PR #3 lands.

## Global Constraints

- Pure is the default, and in Pure every sample handed to iOS is bit-identical to today's path (spec §4.8 "Pure mode", §6.2 "Pure mode is bit-identical").
- Every effect is off by default (§4.8). Turning any block on makes the strip say `● Processing` (§5.7). It never says "bit-perfect" (§5.7); the strongest claim stays "Untouched by pointFlac".
- **Render-thread code allocates nothing, takes no locks, logs nothing and causes no ARC traffic.** Classes are reached through `Unmanaged` unretained references, the established pattern in `RenderSource`.
- DSP internals run in Float64 (§5.2: "DSP graph in Float64"). Biquads are in double precision (§11 RBJ row).
- **Licences:**
  - No GPL, LGPL or AGPL code.
  - Every bundled third-party work goes in `App/ThirdPartyNotices.txt` and the licence guard in `scripts/test.sh` stage 1.
  - OPRA requires its logo and each preset author's credit in the UI.
  - AutoEq *results* are never bundled; only user import of `ParametricEQ.txt` is allowed (§4.8).
- **Platform and code style:**
  - iOS 26.0 and macOS 26.0 package platforms.
  - `swift format lint --strict` must pass.
  - Conventional Commits, authored with the repo-local identity.
- **Testing:** every new render-thread type is covered by the thread-sanitizer stage of `scripts/test.sh`. Run it in its own `swift test --sanitize=thread` invocation, so its CPU load doesn't skew the pipeline's latency checks.

## Rulings made while planning

- **R4-1: interactive DSP runs on the render thread, at the output rate.** Spec §5.2 draws the graph before "output format", and §4.8 lists the resampler last. The pipeline already resamples on the decode thread, half a second ahead of output, so DSP there would make an EQ drag lag by up to 0.5 s. Running DSP at the output rate also designs filters for the rate actually used, and keeps the limiter truly last. Cost if wrong: the block order would move back to the decode thread, and only `SoundChain`'s call site changes.
- **R4-2: EQ filters use Vicanek's "matched second order digital filters" (2016), not plain RBJ.** RBJ's bilinear transform cramps responses near Nyquist: a 16 kHz shelf at 44.1 kHz is off by decibels. Matched designs keep the analog magnitude up to Nyquist without oversampling, which is what high-end EQs aim for. RBJ (§11) remains the reference for filter *definitions*: which gain, Q and slope mean what.
- **R4-3: "Hi-Res" follows Apple Music's convention.** The output is Hi-Res when the hardware receives at least 24 bits at a rate above 48 kHz on a lossless route. Up to 48 kHz it is "Lossless". Bluetooth and AirPlay are neither: the strip already says lossy or re-encoded. The badge always describes what is **delivered**, never just the file.
- **R4-4: crossfade (not in the spec) defaults to Off**, because gapless albums are the product (§4.3).
  - Modes: Off, Between albums (only where an Up Next record follows; never inside a record) and Always.
  - Duration: 1–12 s, default 6 s, with equal-power curves.
  - It applies only when both items share an output plan; otherwise the join stays gapless.
  - Pure disables it.
- **R4-5: tone controls (not in the spec) extend §4.8 block 5 ("Tilt / warmth")** into one Tone block:
  - bass: low shelf at 100 Hz, ±12 dB;
  - treble: high shelf at 10 kHz, ±12 dB;
  - tilt: ±6 dB around 1 kHz;
  - a Warmth preset.
- **R4-6: the limiter is in the chain whenever any block is on (never in Pure).** It has unity gain until a true peak would cross the ceiling, which defaults to −0.3 dBTP. That is how §4.8's "only active when needed" is met without a latency jump each time it engages.
- **R4-7: the default ReplayGain reference is RG 2.0's −18 LUFS.** Gains come from tags, then from scanned R128 values. With neither, the gain is 0 dB.
- **R4-8: no decompiling of proprietary EQ apps.** Quality comes from published research (Vicanek; ITU-R BS.1770-4; EBU Tech 3341/3342) and permissive code (libebur128, bs2b, the AutoEq file format).

## Not in this plan

These are recorded so that nobody mistakes them for omissions:
- **A user-forced output rate** (§4.8 block 8): the resampler stays automatic.
- **Blind A/B:** the spec marks it a stretch goal.
- **Turntable sounds** (§4.3): their own plan; Task 9 removes the placeholder row until then.
- **Linear-phase EQ:** a later option; the matched minimum-phase designs come first.
- **32-bit passthrough to verified DACs:** it needs hardware testing (§6.6).

## Review Focus

1. **A rate change between tracks while EQ is on**, such as 44.1 kHz to 96 kHz across a plan change. The chain must be recompiled for the new rate before the first frame at it. Pinned in Task 7.
2. **Extreme settings.** Twenty bands at +24 dB and Q 20, bands near Nyquist at 44.1 kHz, and tone and graphic EQ at their limits. These must never produce NaN or Inf, unstable filters, or output above the ceiling. Pinned in Tasks 1, 4 and 6.
3. **A finger dragging an EQ handle**, about 120 chain installs a second for seconds. There must be no clicks, no unbounded memory, and every old chain must be freed. Pinned in Task 6.
4. **Mono and multichannel files.** Crossfeed is skipped for anything that isn't stereo; every other block handles 1 to 8 channels. Pinned in Tasks 5 and 6.
5. **Stored settings from an older or corrupt build** must load as Pure defaults, never crash or play garbage. Pinned in Task 9.

**Files:**

**Interfaces:**

  - `public struct BiquadCoefficients: Sendable, Equatable { public var b0, b1, b2, a1, a2: Double }`, normalised so that a0 = 1.
  - `public static func design(_ type: FilterType, frequency: Double, gainDb: Double, q: Double, sampleRate: Double) -> BiquadCoefficients`. These are Vicanek's matched designs. The frequency is clamped to `0.49 × sampleRate`; Q to `0.1…20`; gain to `±24`.

- [ ] **Step 1: Write the failing tests** in `BiquadTests.swift`, a `@Suite("Matched biquads")`:
  - `matchesAnalogNearNyquist`: a high shelf at 16 kHz, +6 dB, Q 0.707, at 44.1 kHz. At 18 kHz and 20 kHz, `abs(magnitudeDb - analogMagnitudeDb) < 0.25`.
  - `peakHitsItsGain`: a peak at 1 kHz, +9 dB, Q 1.41. Check `abs(magnitudeDb(1000) - 9) < 0.01` at 44.1, 48, 96 and 192 kHz.
  - `passesAreRightAtCutoff`: LP and HP at 1 kHz, Q 0.7071, give −3.01 dB ± 0.05 at 1 kHz; the LP gives `< −40` at 20 kHz.
  - `notchIsDeep`: a notch at 1 kHz, Q 4, gives `< −60` dB at 1 kHz.
  - `stableEverywhere`: across every type, f ∈ {20, 1k, 10k, 0.45·fs}, gain ∈ {−24, 0, 24}, Q ∈ {0.1, 1, 20} and fs ∈ {44.1k, 48k, 96k, 192k, 384k}, the poles satisfy `|a2| < 1` and `|a1| < 1 + a2`, and processing 10 000 samples of white noise produces only finite output.

- [ ] **Step 3: Implement the designs from M. Vicanek, *Matched Second Order Digital Filters* (2016).**
  - **Poles:** use matched-z poles, `exp(−ζω₀T ± jω₀T·√(1−ζ²))` for ζ < 1, and the paper's real-pole form otherwise.
  - **Zeros:** choose numerator coefficients so the magnitude matches the analog prototype at DC, at Nyquist and at the analog peak or centre frequency. These are the paper's three-point matching equations for each type. The notch keeps its zeros on the unit circle at f₀.

### Task 6: The compiled chain and its real-time runner

**Files:**
- Create: `Packages/PointFlacKit/Sources/PFDSP/SoundChain.swift`
- Test: `Packages/PointFlacKit/Tests/PFDSPTests/SoundChainTests.swift`

**Interfaces:**
- Consumes: Tasks 1–5.
- Produces:
  - `public final class SoundChain: @unchecked Sendable`, immutable once made.
    - `init(_ s: SoundSettings, sampleRate: Double, channels: Int)`.
    - It holds preamp gain (auto headroom plus trim), correction, EQ and tone biquads per channel, crossfeed (stereo only, Review Focus 4) and a limiter.
    - `let latencyFrames: Int`.
  - `public final class ChainRunner: @unchecked Sendable`:
    - `init(maxFrames: Int = 4096, maxChannels: Int = 8)`, which preallocates its Float64 scratch.
    - Main actor: `func install(_ chain: SoundChain?)`, where nil means Pure.
    - Render thread: `func process(_ io: UnsafeMutablePointer<Float>, frames: Int, channels: Int)`.
    - `var meters: SoundMeters { get }`, a struct of `peakDbFS`, `clipCount`, `gainReductionDb` read from atomics.
  - **Install protocol:**
    - `install` publishes through `Atomic<UnsafeMutableRawPointer?>` (an Unmanaged retained pointer).
    - The render thread picks it up at block start and runs old and new chains in parallel over 10 ms, with an equal-gain crossfade.
    - It then releases the old chain's pointer into a lock-free retire slot. The main actor drains that slot on the next `install` or a 100 ms timer, using the `rendering` flag handshake that `ScrubTap.retireWindow` uses.
  - **Pure:** with a nil chain and no crossfade in flight, `process` returns without touching `io`, so output is bit-identical.
